# First awakening — future separate authorization only

This document is a procedure, not an authorization. Do not instantiate an event or grant merely by following preparation steps.

1. **Verify original identity/state:** seven decisions, zero V2 episodes, original birth/history/snapshot, CLOSED, disabled schedule, no continuous scope; compare reviewed row export. Unexpected difference: stop.
2. **Verify restore:** managed backup plus successful isolated restore drill, external incident/dispatch record and rollback plan. Consumers absent.
3. **Verify services:** exact immutable Node24/Linux image, deployment release, `/health`, `/readiness`, public-safe observer, DB role/TLS limits and private operator access. A hash from macOS is not the production runtime identity.
4. **Inspect first context privately:** identity/history facts, current neutral event schema, saved-only biology, permissions/constitution and computational resources. Review individual disclosure sources for INTERNAL_USE, PROVIDER_DISCLOSURE, PUBLIC_DISCLOSURE separately. Do not approve all seven legacy memories by default. Unknown consent remains excluded; missing historical context must be explained honestly.
5. **Select and admit provider separately:** exact protocol/model/rate-card/counting/retention/secret reference, one attempt, at most $0.05, at most 12,000 input and 1,200 output. Counting/pricing that cannot establish a ceiling refuses dispatch. Native vendor adapter compatibility must be proven. No API-key-only activation.
6. **Sanitized smoke:** obtain separate non-canonical smoke authorization; inspect exact request/ceiling, run once using the admitted endpoint, reconcile usage/billing and failures. No canonical life event. Any uncertain charge remains unresolved.
7. **Freeze identities:** image/runtime/constitution/policy/mode/event, admission, permission hash and state revisions. Privately inspect neutral factual envelope schema. The consumer creates the actual factual event only after a valid claim; preparation does not fabricate it.
8. **Propose grant:** authenticated `propose_grant` with `makeGrant`-compatible exact payload, expected seven decisions and one logical cycle. A proposal is not authority. Independently review the stored row/hash and permission/model/ceiling bindings.
9. **Authorize only after explicit human decision:** authenticated `authorize_grant`, exact current row hash. Keep execution CLOSED and schedule disabled. No continuous scope.
10. **Launch one private consumer:** prepare strict JSON matching `consumerRequest` in `runtime/deployment/consumer.ts`: new immutable launch ID, `mode:"one-shot"`, exact target grant row hash/runtime identity/organism/birth, admitted provider ID and review reference, bounded session. Set `GENESIS_CONSUMER_MODE=explicit`, separate operator/worker DB credentials, auth file/credential and admitted secret; run `node runtime/deployment/consumer-cli.ts < PRIVATE_REVIEWED_LAUNCH.json`. No public HTTP route can do this. This command consumes already-issued authority, never issues it.
11. **Stop and inspect:** Decision 8 at most; grant CONSUMED or failed/ambiguous terminal status; no Decision 9. If output/acknowledgement is uncertain, inspect durable state; do not relaunch with another ID to bypass uncertainty.

## After Decision 8

Privately verify decision schema, bounded rationale, proposal-policy-intent-outcome agreement; actual local effect vs abstention/denial; episode and Life State revisions; context/memory/source/disclosure provenance; immutable provider receipt, reservation, actual/unknown cost; artifact/project/task changes; truthful public DTO; biology NOT_APPLIED and identical biological snapshot; no external effects or hidden scope; consumed one-shot grant; CLOSED execution; schedule disabled.

Abstention is valid. No required personality, project, enterprise, financial goal or dramatic narrative is scripted. Preserve every failed gate and unknown outcome.

**Stop for human review.** Paid continuous reasoning is not implemented/admitted here. A future continuous-local scope, independent reviewed launch and explicitly bounded local session are separate authority. Wallet, internet, messages, external execution and biological advancement remain disabled. No default process proceeds from Decision 8 to 9.
